# 2026-11-03

## 号池「停用不生效 / 总跳旧号」根因修复

用户反馈：后台停用了 8613979487671，站点仍显示并跳这个号；且不管显示哪个号，点击最终都跳 15190068041。

### 三个真实根因

1. **配置和统计共用同一个 KV 键 `wa-pool`**
   `functions/api/wa/next.ts` 每次点击都 load → record → save 整份文档，把 `numbers[].active` 一起写回。KV 最终一致，一个早几百毫秒读到旧数据的点击请求会把整份写回，**覆盖掉后台刚做的停用**。表现就是「三个号又全是 active:true」。
2. **`pickNumber` 在没有启用号时 `return pool.numbers[0]`**，不检查 active → 全停用后仍下发第一个号（正好是老号）。
3. **客户端把分配结果缓存 10 分钟并直接跳转**（`sessionStorage` + `routeWaUrl` 的 `|| readTarget()`），以及兜底链里的静态快照 `wa-pool.json` 和写死的 `WHATSAPP_NUMBER` 都指向旧号。

### 改法

- KV 拆成两个键：`wa-pool`（配置：号码/启用/权重/国家/日上限）、`wa-stats`（计数：clicks/uv/refs）。点击只写 `wa-stats`，永远碰不到配置。
- `loadStats` 首次读取时把旧文档里内嵌的计数迁移过来**并立即落盘**（否则下次配置写入会把旧计数抹掉，已踩过）。
- `pickNumber` 无启用号时返回 `null`，`next` 返回 `503 {error:"no_active"}`。
- 删除 `frontend/public/wa-pool.json` 与 `scripts/sync-wa-pool.mjs`（含 `npm run sync:wa`）；客户端不再读任何构建时快照。
- `lib/waLink.ts` 重写：点击一律问服务端，缓存只记「聊过哪个客服」的 id（`prefer`），不记号码。`routeWaUrl` 返回 `null` 时弹「客服正在接入」卡片，绝不跳停用号。
- `_blank` 链接改为**同步 `window.open("about:blank")`** 再 `tab.location.replace(url)`，避免 await 之后弹窗被拦。
- 落地页 `assign()` 去掉 `fallbackPhone`，无可用号返回 `ok:false` → 落地页弹同款提示卡。
- 后台状态按钮文案从「启用/暂停」（像动作，实为状态）改成「接单中 / 已停用」，表头加「点击切换」；全停用时显示黄色告警条。

### 部署踩坑（重要）

`wrangler pages deploy` 之前出现「部署成功但访问 404 / 文件数 0」，原因是 `node_modules/.cache/wrangler/pages.json` 上传清单被一次失败发布污染，wrangler 以为文件都传过了。**删掉这个文件再发布即可**，比换项目/回滚都有效。

## 权重与「总是同一个号」的解释

- 权重 = **新访客**的分流比例，数字越大分得越多（1:3 → 约 25%/75%），不是优先级。实测 60 个新访客得 80/20（n=60 的正常波动）。
- 用户「启用了两个号却总是显示权重 1 的那个」，原因是**粘性**：浏览器记 `tideora-wa-prefer`，老访客固定回原客服，权重只影响第一次分配。
- 后台已加：权重列显示 `1 · 25%` 这样的实际占比；表头加「重新分配我的会话」按钮（清 sessionStorage `tideora-wa-prefer` / `tideora-wa-target`、localStorage `tideora-wa-number`）；底部说明补了权重方向与粘性解释。

## 浮动 WhatsApp 按钮悬停号码不跟随后台

现象：后台改了客服号码，站点右下角浮动图标悬停仍显示旧号。

原因：`ContactFloat` 的号码来自 `lib/api.ts` 里 `/contact` 的写死常量 `WHATSAPP_NUMBER`，跟号池无关。

改法：`lib/waLink.ts` 新增 `peekWaTarget()`（走 `/api/wa/next?peek=1`，不计数；失败再退 `/api/wa/public` 按权重挑）；`ContactFloat` 挂载时取一次，之后 60 秒 + `focus`/`visibilitychange` 刷新；标签按 `+86 130 1392 5997` 分组显示，`title` 显示客服名。始终渲染 `<a>`（不再用按钮兜底），接口抖动时点击仍由路由器处理。

注意：跨境 RTT 约 1 秒，标签会短暂显示「…」，这是正常的。

## 环境备注

- 本地 `npm run dev`（127.0.0.1:3000）把 `/api/wa` 代理到线上，所以本地后台改的就是线上号池。
- Node 里 `VAR=x node -e '...' "$VAR"` 时 `$VAR` 在赋值前展开，会拿到空值；要用 `VAR=x; node ...`。
- Playwright 测 `wa.me` 跳转要等 5–6 秒才看到 `api.whatsapp.com/send?phone=`，3 秒时还是 `about:blank`，别误判。

抠图（关键）：`scripts/cutout_vials.py` 用 Pillow 做「色差 alpha + 解混」而不是描边——
`a = max(clamp((8-(B-R))/6), clamp((215-luma)/40))`，再由 `observed = a*C + (1-a)*B` 反解 `C`。
背景偏冷（B-R≈10），标签白/深字/银盖偏中性，所以这套判据很稳；半透明玻璃会自然透出面板色，无需描边。
后处理：去掉角落暗角连通块、砍掉地面阴影带（按行取实心区左右边界裁剪）、alpha<120 归零、bbox 裁切。产出 `frontend/public/images/lp/{semaglutide,tirzepatide,retatrutide,ipamorelin,slu-pp-332}.png`（约 750×1366，透明底）。
教训：`floodfill` 阈值法在渐变背景上会留「翅膀」状残留，色差解混干净得多；numpy 没装，纯 Python BFS 做连通块在 800px 下够快（5 张约 15 秒）。
