## 第三轮：停用号码后仍跳旧号的修复

现象：管理员新增客服、停用旧号后，全站仍跳旧号。线上号池数据是对的（旧号 `active:false`，`/api/wa/next` 也返回新号），所以问题在客户端兜底链。

根因三条：
1. `frontend/public/wa-pool.json` 是构建时快照，里面旧号还写着 `active:true`
2. `lp/wa.ts` 的 `pickLocal()` 在没有启用号时 `return pool.numbers[0]`，会返回**被停用的号**
3. `lib/api.ts` 的 `WHATSAPP_NUMBER` 写死旧号，是所有兜底的最后一道

修法：
- 新增 `functions/api/wa/public.ts`：只返回启用中的号（不含统计），客户端兜底用它而不是静态文件
- `lp/wa.ts`：`loadStaticPool` 先请求 `/api/wa/public` 再用 `wa-pool.json`；`pickLocal` 无启用号返回 `null`，绝不返回停用号
- `lib/waLink.ts` 重写：页面加载时 `primeWaTarget()` 预热号码，点击走**同步** `window.open`（实测 38ms，之前要等 2s）；每次点击用 `keepalive` 请求计数；新增 `publicPhone()` 兜底
- 新增 `scripts/sync-wa-pool.mjs` + `npm run sync:wa`，`deploy:cf` 里先同步再构建，静态快照跟着号池走（不需要 token，走 public 接口）
- `lib/api.ts` 的 `WHATSAPP_NUMBER` 改成当前启用号 `8613979487671`

验证：屏蔽 `/api/wa/next` → 走 public 接口仍得新号；屏蔽全部 `/api/wa/*` → 硬编码新号；四个入口（首页浮动、产品页询价、落地页产品卡、落地页顶部）全部新号。

**遗留注意**：停用号码对已打开页面的访客最多 10 分钟（sessionStorage TTL）才失效；要立刻切断就删号而不是停用。

## 环境备注

- 本机 `wrangler pages dev` 的 workerd 会崩（stack overflow / 0xc0000005），Functions 只能用 `wrangler pages functions build` 验证打包；静态预览用 `npx serve dist -s`。
- 本机 curl 需要 `--noproxy '*'` 才能访问 localhost。
- Node 脚本里写 `/tmp/x.png` 会落到 `C:\tmp`，不是 Git Bash 的 /tmp。
- Playwright 浏览器没装（`ms-playwright` 空），用 `chromium.launch({channel:"chrome"})` 走系统 Chrome；模块在 `~/AppData/Local/npm-cache/_npx/e41f203b7505f1fb/node_modules/playwright`。
- `vite build` 到 `dist` 会撞 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`（dist/images 203 文件），改 `--outDir dist-deploy`。
